# 307 - Render, settings, and slash feedback polish

## Findings from 02_2048 and 09_blockblast

- `02_2048` renders board tiles in Pixi, pools tile containers, caches the static board background as a texture, and uses transform-based GSAP animations for movement/pop feedback.
- `09_blockblast` keeps a separate Pixi canvas layer for board/pieces/animations, preallocates particle sprites, caps renderer resolution, pauses the ticker when the game is paused, and runs combo shake inside Pixi ticker instead of React state.
- Both settings screens use the same visual pattern: a cream card, icon-led rows, pill buttons, strong border/shadow, and constrained mobile-safe sizing.

## Current FruitSlashing state

- FruitSlashing already uses PixiJS for the playfield, caps mobile resolution, pools splat particles, pools slash Graphics, throttles HUD updates, and avoids trail redraw when empty.
- The likely mobile pain point while slashing is input frequency plus perceived feedback: pointermove can call gameplay and React floating-text updates more often than the frame rate, while normal fruit slices have no screen shake.
- Settings works, but it is still a narrow inline panel and does not match the 2048/BlockBlast settings component style.
- The "Chém Lạc Vùng Cao" identity is readable, but the title can feel flatter than the rest of the animated game presentation.

## Implementation plan

1. Coalesce pointermove handling with `requestAnimationFrame` so mobile slash input runs at frame cadence while pointerdown remains immediate.
2. Add a light normal-slice shake path in Pixi feedback and keep bomb shake stronger.
3. Schedule Pixi resize work through RAF and visualViewport resize hooks to reduce layout thrash on mobile browser chrome changes.
4. Restyle `SettingsPanel` into the same component language as `02_2048` and `09_blockblast`: icon header, setting rows, pill action button, and stat rows.
5. Add stylized floating title treatment for "Chém Lạc Vùng Cao" on hero and game top bar using CSS transform/opacity animation.
6. Validate with TypeScript and production build.
